---
title: "Execd authentication for agent-sandbox workloads"
description: "Per-sandbox execution tokens and classic-mode initialization hardening."
---

Agent-sandbox workloads use the server's Pod-IP proxy. Keep execd's listener
reachable on that interface. Binding the whole daemon to loopback would break
this transport.

New agent-sandbox workloads receive a random execution token, generated by the
server after merging the pod template. The server stores it in the Sandbox
annotation `opensandbox.io/execd-access-token` and injects it into the sandbox
container as `EXECD_ACCESS_TOKEN`. Each workload gets a different token. The
provider enforces classic startup (`EXECD_RUNTIME_INIT=false`), since this
provider has no runtime-binding initialization caller.

Endpoint resolution supplies `X-EXECD-ACCESS-TOKEN` only for port 44772. The
HTTP/WebSocket proxy replaces any caller-supplied spelling of that header with
the trusted endpoint value. Other application ports do not receive the token.
Treat workload metadata and endpoint responses as private credentials.
Signed, expiring endpoint responses do not include the permanent execution
token. The agent-sandbox template must contain exactly one container named
`sandbox`; invalid templates fail before creating a workload.

Execd no longer registers `/internal/init` when runtime-init is disabled.
Liveness and readiness remain accessible without a token. Explicit runtime-init
mode keeps its existing internal protocol; this patch does not qualify that
mode for untrusted networks. A workload can read its own token: this protects
against network peers, not code already running inside the same sandbox.
The BatchSandbox provider is outside this patch and receives no new protection
if it is enabled later.

Deploy the paired server and execd images at an empty-lane boundary. Existing
guests are not retrofitted, and a route-only daemon update does not authenticate
tokenless guests. Keep NetworkPolicy in place. Verify missing/wrong tokens and
initialization attempts fail, correct-token exec and file operations succeed,
and tokens from another guest fail. Record immutable image digests and perform
the lifecycle and client smoke checks on each affected deployment.
